# Issue 003 候选结论怎样获得支持

状态：本期已实现一个整数系数单变量多项式恒等式检查器；没有调用AI生成候选，没有运行Lean，也不是通用自动定理证明器。候选式是人为设计的教学例子，模拟“拿到一段答案后如何核查”的流程，不冒充真实模型评测。

目标：区分“找到反例”“有限抽样通过”“在限定表达式语言中做精确代数检查”。前置为初中代数；基础层25分钟，实践层15分钟。

## 三种证据的差别

| 证据 | 可以得出什么 | 不可以得出什么 |
|---|---|---|
| 一个反例 | 一个全称命题在该点不成立 | 所有其他点都不成立 |
| 若干点代入都正确 | 这些点未发现错误 | 所有整数或实数都成立 |
| 两边多项式精确展开后同系数 | 在所支持的多项式代数中是同一个多项式 | 任意自然语言证明、分式或几何命题都已验证 |

## 先看两个候选式

A：(x+1)² = x²+2x+1。两边展开同为x²+2x+1，差多项式为0。

B：(x+1)² = x²+1。两边相减为2x，并非零多项式；x=1时左边4、右边2就是反例。文字解释再流畅，也不能弥补少掉的2x。

程序使用字典表示多项式，例如`{2:1, 1:2, 0:1}`表示x²+2x+1。加法按同次幂合并系数，乘法将次数相加、系数相乘后合并。全程使用整数运算，没有浮点近似；语法树只接受x、整数、加减乘和有界非负整数次幂。

从常数和x出发，这些运算保持表达式代表的多项式不变。最终两边之差的系数都为0时，得到的是同一多项式，因此在所有整数x取值下相等。结论仍依赖程序正确实现及输入命题正确表达，并不拥有Lean内核级的验证保障。

## 设计一个会骗过抽样的例子

令P(x)=x(x−1)(x+1)(x−2)(x+2)(x−3)(x+3)。在−3至3的每个整数上，P(x)=0，但它不是零多项式，最高次项是x⁷。x=4时P(4)=5040。

[检查器](../../demo/identity_checker.py)会同时报告`identity=False`和`counterexample=None`。这里的None只表示预设抽样范围未找到反例，**不表示恒等式成立**。精确系数比较给出的结果与有限反例搜索分别保留，避免把不同证据混为一谈。

## 练习与参考答案

1. 候选式`(x-1)*(x+1) == x**2-1`是否恒等？**答案**：是，分配律展开后两边同系数。
2. 候选式`x*(x-1)*(x+1) == 0`在−1、0、1都成立，能否算恒等？**答案**：不能，x=2时为6。
3. 为何拒绝`x/x == 1`？**答案**：分式不在支持语言内，而且x=0处有定义域问题，不能为了得到“通过”忽略前提。
4. 使用`x^2`会怎样？**答案**：本程序拒绝；代码中的幂必须写`x**2`，`^`不是这里的幂运算。
5. 检查出一个恒等式，能否宣称自动验证所有AI数学答案？**答案**：不能，只覆盖限定的代数表达式。

## 实践与前沿联系

让参与者先在纸上分为“正确”“错误”“条件不明”三类，再运行脚本。每人记录一个分歧及原因，不收集谁答错了。将“候选生成”和“结果验证”分开，是讨论AI辅助数学时的一种思路；本演示只实现后一部分中的小范围检查。
