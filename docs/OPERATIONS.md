# π Frontiers 六周试运行执行方案

本方案是可供部门讨论的执行设计。人数、时间、分工与预算都是建议；没有已招募成员、已批准场地或已开展活动。

## 服务对象与学习分层

目标是让低年级学生知道如何提问、寻找原始资料、区分结论与证据，并完成可解释的小实践。先用3—5人体验校准内容；体验顺利且获部门同意后，再考虑8—15人的小组。报名不设置编程门槛。

| 层次 | 起点 | 活动内任务 | 留下的证据 |
|---|---|---|---|
| 入门 | 对主题好奇，无程序基础 | 看中文问题说明，做手算或找错题 | 一张练习卡，能复述一个关键点 |
| 实践 | 愿意读代码或补基础 | 改动一个输入，预测结果，再运行核对 | 输入、预测、输出、差异解释 |
| 延伸 | 有时间继续钻研 | 找到原文相关段落，提出验证问题 | 一页阅读卡或小实验计划 |

不把三个层次当作学生等级。每个人可按时间选择；进阶任务不挤占基础讲解，不以“学过某软件”决定参与资格。

## 六周安排和阶段门槛

以部门同意后的第1周为起点，不编造实际开办日期。频率为两周一次，三场主题的编号是主题类别，不是强制授课顺序。

| 周 | 工作与责任 | 交付与进入下一步的条件 |
|---|---|---|
| 第1周 | 协调人收集3—5份自愿需求回应；主讲人试讲数学基础；复核人审读关键论证 | 一份需求汇总、一次内部试讲；关键错误修正后才能发活动通知 |
| 第2周 | 开展Issue 002，30分钟；记录员收题卡及耗时 | 能区分列举与证明；复盘后决定是否继续 |
| 第3周 | 准备Issue 001注意力演示，确认向量与加权平均前置 | 导读、预测题、程序输出一致；不能解释的部分删去 |
| 第4周 | 开展Issue 001，40分钟；增加一页论文阅读卡 | 至少记录实际完成练习人数和一个常见误解，不预填人数 |
| 第5周 | 准备Issue 003候选结论核查；整理参与者提出的问题 | 区分反例、有限抽样、符号归一化；明确工具只接受有限语言 |
| 第6周 | 开展Issue 003，40分钟；汇总三场体验 | 决定继续、改为讲座配套或暂停；最多挑一个小问题做后续实践 |

每场“通过”不是考试分数，而是活动准备门槛：问题清楚、来源可定位、练习可完成、答案可靠、时间可控、协作有人承接。

## 活动前七天到活动后的工作清单

| 时点 | 操作 | 文件或可检查结果 |
|---|---|---|
| T−7天 | 主讲人确定唯一核心问题和先修要求 | 主题卡：对象、目标、材料、练习、局限 |
| T−5天 | 资料整理人核对来源；复核人检查证明/代码 | 阅读卡与问题清单；不确定项单列 |
| T−3天 | 内部试讲；协调人按部门流程确认场地、时间及通知 | 实际计时；关键错误已解决；通知信息一致 |
| T−2天 | 如获准发布通知，收自愿参与意向，不承诺证书/加分 | 人数汇总；不用真实报名信息进入公开仓库 |
| T−1天 | 冻结讲义版本，测试离线文件和代码；分开答案 | 最终材料目录、备用输出、主持分工 |
| 当天 | 按主持表执行；记录实际到场、题卡完成、超时情况 | 匿名汇总，不把到场人数等同学习成效 |
| T＋1天 | 整理反馈、纠正错误、发经允许分享的资料 | 修订记录、未解问题和一项改进 |
| T＋3天 | 决定继续/调整；归档材料供下一位成员接手 | 复盘结论及下一次范围，不无限追加任务 |

## 人员分工和协作边界

建议2—3名志愿协作者，不设置新组织层级。协调人与记录员可以兼任，但关键内容尽量由另一人交叉检查。未找到复核人时可继续内部准备，暂缓正式分享。

| 角色 | 负责什么 | 不自行决定什么 |
|---|---|---|
| 协调人 | 时间安排、材料收集、提醒缺项、汇报进展、归档 | 场地占用、官方账号发布、活动立项和预算 |
| 主讲与内容整理人 | 导读、练习、代码解释、来源与局限 | 不宣称未理解的结论，不代老师作专业背书 |
| 复核人 | 查看关键推理、例子、运行结果、可读性 | 不将一次看稿写成正式学术认证 |
| 记录员 | 实际人数、时间、匿名难点和后续需求 | 不公开同学个人信息，不编造满意度 |

需要融媒体宣传、多媒体设备或办公室资源时，由负责人按原有流程协调；计划发起人不能先承诺其他部门提供资源。

## 时间和资源预算

每期资料准备合计约4—6人时：选题和来源1小时、讲义和练习1.5小时、演示与核对1小时、交叉审阅0.5—1小时、排程与归档0.5小时。由2—3人分担，单人尽量不超过每两周2—3小时。首次掌握新知识可能更久，超过预算就减内容或延期。此前v0.1的2—4小时只适用于基础主题和熟悉材料，不能直接套到更深入的三期版本。

计划现金支出以0元为目标：优先现有设备与电子讲义。若确需打印、交通或其他费用，列数量与用途，按部门流程确认后发生；这里不承诺已有预算，不采购GPU、会员或模型API。电脑用于运行三个标准库脚本；不需要参与者安装整套竞赛软件。

## 评价与止损

每次保留实际分母：到场人数、交回题卡人数、关键题解释正确人数、愿意继续且实际回应人数。比如报告“3/5交回题卡”，不将未回应者自动归类。小样本只用于改进，不声称项目有统计学效果。

改进决策建议：超过半数交回题卡的人说不清关键区别时，下一次先补基础；准备连续两次超出6人时，降低频率；人数少先询问时间或选题原因，不强制参与；关键内容无法可靠审核、没有人能承接或与部门事务冲突时暂停。

## 从阅读到大创或竞赛的实际衔接

| 现有工作 | 活动能提供什么 | 转化前还缺什么 |
|---|---|---|
| 科创讲座 | 会前问题导读、会后练习、同学问题汇总 | 与讲座主题匹配、主办方同意 |
| 青创营等特色活动 | 选题讨论、资料检索和表达练习 | 具体活动规则、组织安排 |
| 数学建模 | 假设、变量、基线、实验及局限的写作意识 | 真实建模问题、合适数据、团队与当届要求 |
| 大创 | 一页问题卡、初步来源、小验证记录 | 教师指导、研究价值、资源与正式申报资格 |
| 创新创业赛事 | 对一个技术想法进行小验证 | 用户需求、应用场景、团队、合规数据和赛事条件 |

示范：注意力活动后可研究“改变向量尺度怎样影响权重分布”。先明确输入和比较方法、保存数值表，再查原文讨论。这个小实验可以训练研究习惯，但本身不称创业项目、大创成果或论文复现。

## 风险处理和交接

| 情况 | 当场动作 | 后续处理 |
|---|---|---|
| 没人参加 | 不制造签到；改为内部试讲 | 询问需求，再决定主题和时间 |
| 讲解太难 | 停进阶内容，回到给定数值例子 | 把生词和前置知识移到导读开头 |
| 被指出错误 | 暂停该结论，标待核实 | 修正原文件和分发版本，记录影响 |
| 程序失败/断网 | 展示已保存输出，说明不是现场运行 | 复现问题，修复后再更新记录 |
| 临时部门任务 | 先与负责人协调，延期可选试点 | 交接已有资料，不让同伴猜进度 |
| 人员退出 | 缩减到能维护的一期 | 按目录交接：来源、讲义、测试、未解问题、复盘 |

每期归档保留日期、版本、作者/整理角色、原文来源、核验范围和未解问题。不要把“文件写完”“代码跑通”“自己已掌握”“活动已举办”合并成一个完成状态。
