# 怎样把一篇论文变成可以讨论的问题

目标不是一次读懂整篇，而是知道哪些理解有依据、哪些仍然不会。首轮预算45分钟：10分钟判断相关性、20分钟定位一个问题、15分钟做阅读卡。遇到先修知识缺口应记录，不让AI摘要替代原文。

## 第一轮看问题而不是逐句翻译

先记作者、年份、标题、版本和发表状态。预印本不自动等于已被会议接收，最新上传日期也不必然是首发年份。用自己的话回答：作者研究什么问题，为什么原有做法不够，提出了什么办法，用什么支持结论？回答不了的栏先写“未理解”，不拼接术语。

## 不同论文的阅读路线

| 文体 | 先定位 | 再核查 | 常见误读 |
|---|---|---|---|
| 实证机器学习 | 问题、方法图、实验任务 | 基线、数据、指标、消融、局限 | 把某个基准提升说成所有场景有效 |
| 数学理论 | 定义、定理、假设、结论 | 引理和推理依赖、反例、适用条件 | 删掉前提只记结论 |
| 系统或工具 | 功能目标、接口、使用条件 | 实现、验证、性能或可信边界 | 把工具成功运行说成完全正确 |

Abstract帮助判断方向；Introduction定位问题；Related Work定位与既有工作的关系；Method说明方法；Experiment说明实验依据；Proof给出论证。不是每篇论文都具有这些标题，阅读时按功能定位。

## 一页阅读卡模板

| 栏目 | 填写要求 |
|---|---|
| 来源 | 标题、作者、年份、原始链接、所读版本与章节 |
| 一句话问题 | 去掉缩写，向同学解释作者想解决什么 |
| 三个必要概念 | 给定义或例子，不超过三项 |
| 核心方法/定理 | 写一张图、一个公式或一个明确命题 |
| 证据 | 原文哪张表、哪段证明支持哪句话 |
| 我亲自做的验证 | 一个手算、输入改动、反例检查或小程序 |
| 没有做的事 | 未复现完整训练、未读附录、未审阅全部证明等 |
| 下一步 | 一个能在一小时内进一步检查的问题 |

## 检索和审核路径

先从精确标题、作者或关键词找到候选，再回到作者论文、会议论文页、arXiv版本页或官方文档。搜索引擎和社交媒体是找线索的途径，不是最终依据。保存实际链接和访问日期；打不开全文时不要只凭别人转述写出确定结论。

对每条重要主张标四类：原文明确陈述、根据原文推导、教学类比、尚不确定。讲义可以使用类比，但要写出类比在哪一步失效。AI可辅助解释生词、提出检索词或检查代码，最终仍回看原文与结果。

## 本仓库的完整阅读卡示范

Issue 001：[Attention Is All You Need](https://arxiv.org/abs/1706.03762)，Vaswani等，2017；本次仅取第3.2.1节的缩放点积注意力公式。问题是如何由查询和键值对得到加权输出。必要概念是点积、缩放、softmax。亲自验证范围为一条查询、两组键值对，比较三种查询的结果。没有进行训练、翻译评测、多头结构或完整Transformer复现。下一步可观察查询尺度变化时权重是否更集中，并说明这个观察不能直接代表模型性能。

## 进入公开分享前的检查

- [ ] 每个关键结论有定位到原文的依据。
- [ ] 输入、公式、代码输出与讲解一致。
- [ ] 知道至少一个失败例子或不适用条件。
- [ ] 能用不依赖术语堆砌的两句话解释核心问题。
- [ ] 已区分学习笔记、教学演示和研究成果。
